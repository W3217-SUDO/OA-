# 8.27 第14行整改验收

## 根因与边界

- 旧系统 `CaseController.CaseCreateUpdate` 保存既有案件时只执行基本信息更新，不检查“新建案件三步”标记。
- 新系统 `PUT /api/v1/cases/{id}/normal-basic` 错误复用了 `_require_case_creation_completed`，导致历史/复制案件即使已处于办理阶段，只要 JSON 中遗留 `case_creation_step=basic` 或 `litigants`，文书保存基本信息就被 409 拦截。
- 整改仅取消“案件详情基本信息维护”接口对新建三步标记的依赖；`case.detail.update` 权限、普通案件类型校验、归档锁、字段校验、审计与持久化均保留。
- 数据库结构无需调整，不修改原始 Excel、旧系统或任何线上数据。

## 自动化验收

- 新增隔离 SQLite 合同测试，证明文书账号具备“案件承办”映射时，可在 `case_creation_step=basic` 的案件上保存基本信息，且标记保持不变并写入审计事件。
- 负向覆盖：缺少 `case.detail.update` 权限时返回 403 且零写入；归档案件返回 409 且零写入。
- 相关回归：第4行阶段审批独立性、旧系统普通案件基本信息契约均继续通过。
- 生产前端构建使用现有版本 `1.0.273` 完成，未改版本号。
