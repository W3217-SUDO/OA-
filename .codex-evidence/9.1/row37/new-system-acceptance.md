2. 实际生成并落入案件文档：8 项成功，均返回 201、创建物理 DOCX、`file_attachments` 与“生成案件文书”事件一致：

   - 执行所函
   - 身份证明
   - 结算提成表

3. 归档封面、授权委托书：菜单可见，但本次精确文本/实时 DOM 点击均未发出 API 请求，SQLite 也无附件；按主会话停止重试指令保留未完成，不能用接口测试冒充 Chrome 通过。
4. 正式模板边界：上述 8 份文件由当前 `_case_document_bytes` 程序拼装，并非用户尚未提供的正式模板。只证明“请求、附件实体、下载文件、分类和刷新”链路可用，不宣称与旧系统正式模板等价。
5. 本人文件删除：选择 `第37行本人上传文件.txt`，确认后 `POST /cases/attachments/delete` 返回 200，页面提示已删除，SQLite/物理文件均移除，并写一条删除审计事件。

7. 原子性：后端聚焦测试已覆盖本人+他人混选整批 403 且零删除；本次 Chrome 分别证明本人成功与他人失败。由于浏览器第一次选中实际只包含本人，不能把它伪写成浏览器混选证据。
8. 更改目录：将生成的“代收代付赔偿款申请单”从“庭审及庭后文件”移动到“起诉材料及证据”，接口 200，页面提示成功，SQLite 分类回读正确，并写一条目录变更事件。
