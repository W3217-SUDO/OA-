# 案件管理 PDF 逻辑对齐清单

更新时间：2026-07-20

## 对齐口径

两份案件管理 PDF 是系统必须具备的最低业务功能。当前系统已有但 PDF 未列出的功能全部保留；不得为了对齐蓝图删除菜单、字段、按钮或流程。用印为独立业务模块，不属于调查模块的子步骤。

## 必须保留的原业务规则

- 任务超过 30 天拒绝。
- 任务交接后可以重新开始。
- 任务交接满 5 天未开始自动完成。
- 合同审批、案件归档、用印、财务、人事、证物均只能走专用流程，通用记录接口不能绕过。
- `admin` 拥有全部菜单、全所数据和全部字段权限。

## 当前外部依赖和确认边界

- 短信服务商尚未确定，系统不会把“未配置通道”伪装成发送成功；正式发送需配置服务商 Webhook 和令牌后再做手机实收验收。
- PDF 说明了岗位名称和主流程，但没有给出每个岗位的完整数据范围、金额字段范围和替岗规则；这些细节仍需律所合伙人按角色确认。
- 本清单证明蓝图最低功能已进入本地代码和自动化业务验收，不等于生产数据迁移、性能压测、HTTPS、安全加固或最终上线已经完成。

## 验收命令

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-local.ps1
```

验收覆盖前端生产构建、Python 编译、菜单与页面结构、前后端路由映射、18 组真实业务 API 流程、测试数据清理和 Docker Compose 配置。
