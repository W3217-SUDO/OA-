# OA 全站快速功能对齐实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在本地 `dev` 分支以最短交付周期补齐申浩旧系统已有而本地系统缺失的页面、按钮、跳转、权限、状态流转和数据闭环，并在全站本地验收完成后统一发布。

**Architecture:** 保留现有 React + TypeScript 前端和 FastAPI 后端，不做无收益的大规模换框架或视觉复刻。四个独立任务按业务域独占文件并行开发；每次只交付一个可独立验收的业务闭环，完成后立即测试、清理数据、串行 Git 提交并续派下一项。

**Tech Stack:** React、TypeScript、Vite、FastAPI、Python、PostgreSQL、现有本地测试脚本与 Codex 内置浏览器。

## Global Constraints

- 旧系统只读；禁止新增、编辑、审批、上传和删除旧系统数据。
- 仅修改本地 `dev` 分支；全站本地完成前不部署服务器。
- 本地已有但旧系统没有的功能保留；只补缺失、修错误，不为像素一致重写已正确功能。
- 临时数据必须使用任务唯一前缀并按精确 ID 清理，禁止删除既有数据。
- 四个任务禁止同时修改同一业务文件；共享文件 `apps/api-server/app/main.py` 采用项目经理发放的独占时段。
- Git 串行提交，只暂存本任务明确文件，禁止 `git add .` 和 `git add -A`。
- 浏览器采用四任务并行固定标签组：A/B/C/D 各自最多保留旧系统只读和本地系统各一个标签，只操作本任务登记的标签 ID；不得关闭、导航或复用其他任务的标签。失效标签只在本任务组内关闭重开。
- 每个闭环必须证明：入口条件、成功路径、失败阻断、状态/数据落库、关联页面刷新、权限限制和数据清理。

---

## 执行节奏

每个业务闭环严格执行以下七步，禁止把多个页面积压到最后一起验收：

1. 在旧系统只读打开当前入口，记录字段、按钮、弹窗、跳转、可见条件和失败提示。
2. 在本地打开同一语义入口，只列“旧有本地缺失”与“本地行为错误”两类差异。
3. 先增加一个能复现差异的定向测试；确认修改前失败。
4. 实施最小修改，不顺便重构无关文件或补无限扩展测试。
5. 运行定向测试、前端生产构建和受影响 Python 编译；确认全部通过。
6. 使用浏览器完成成功与失败路径复验，并精确清理临时数据和无用标签。
7. 向项目经理提交六项报告，获得 Git 时段后形成一个小提交，随后立即进入下一入口。

## 目标层级

- **最终目标：** 全站旧有功能在本地系统中真实可用，差异总表不再包含“确认缺失、部分缺失、仍未证明”，完整本地验证通过后统一发布测试服务器。
- **模块目标：** 每个一级菜单下的列表、新建、详情、编辑、子页面、文件、状态流转和权限矩阵全部形成浏览器与接口证据。
- **迭代目标：** 一次只完成一个可独立拒绝或通过的页面/状态链，必须能单独测试、清理和提交。
- **当前目标：** 先把四个任务现有未提交修改收敛为四个小提交，不继续扩展范围。

## 主会话与四个任务的交互协议

### 1. 派工消息

项目经理每次派工必须写明以下内容，任务不得自行扩大范围：

```text
业务域：事务/案件/合同/用印等
当前入口：准确菜单、页面或状态链
旧站路径：只读对照地址或菜单路径
本地路径：本地路由
允许修改：精确文件或模块边界
必须验证：成功、失败、权限、落库、关联刷新、清理
禁止事项：旧站写操作、服务器部署、越界文件、未授权 Git
完成出口：六项汇报后等待“通过/补证/返工/续派”判定
```

### 2. 任务进度消息

任务只在以下节点主动汇报，减少无效刷屏：开始定位、发现确定差异、完成代码、测试失败需要决策、进入浏览器验收、准备提交。每次消息必须包含“当前动作 + 已有证据 + 下一动作”，禁止只说“处理中”。

### 3. 阶段完成的六项汇报

```text
1. 已完成：准确到页面、按钮和状态链
2. 验证证据：测试命令与结果、旧站/本地页面证据、接口或落库证据
3. 未完成：本入口仍缺失或仍未证明的项目
4. 修改文件：仅列本任务精确路径
5. 清理状态：临时数据编号、清理方式、浏览器保留标签数量
6. 交付状态：可提交/需补证/阻塞；若阻塞写明唯一根因
```

### 4. 项目经理判定

- **通过：** 证据完整，发放唯一 Git 时段；提交后检查提交号和工作区，再续派下一入口。
- **补证：** 功能可能正确但缺页面、权限、失败路径或清理证据；只补指定证据，不改范围。
- **返工：** 行为与旧站业务不一致、使用假按钮/假数据、破坏额外功能或测试未通过；退回同一任务修复。
- **续派：** 当前小提交完成后，立即派发该流水线的下一个菜单入口，任务不得空闲等待。

### 5. 卡点升级

- 定位 20 分钟无明确结论，任务必须提交：尝试过的路径、最后错误、最可能根因、两个可选动作。
- 项目经理在收到卡点后负责缩小范围、调整文件独占权或切换验证手段；禁止任务无限重试。
- 浏览器卡住时先关闭失效标签并重开同一旧站/本地页面；恢复失败后再汇报，不把常规恢复交给用户。

### 6. 共享资源调度

- **Git：** 同一时间只允许一个任务暂存和提交；项目经理明确发送“允许提交 + 精确文件清单”后方可执行。
- **浏览器：** A/B/C/D 各自维护固定双标签（旧系统只读 1 个、本地系统 1 个），可同时执行双页验收。任务首次接管时必须汇报两个标签 ID/URL；只允许导航或关闭本任务标签，禁止操作其他任务标签。每个任务始终不得超过 2 个标签。
- **共享后端文件：** 修改 `apps/api-server/app/main.py` 前必须获得独占权；完成定向测试后立刻释放。
- **任务标题：** 项目经理在派工、待验收、返工和完成时同步改名为 `A/B/C/D｜模块·子功能｜状态`，用户可直接从侧栏查看进度。

## 速度控制与质量门槛

- 单个任务一次只处理一个页面或一条状态链；发现相邻缺失先登记，当前闭环提交后再处理。
- 定位超过 20 分钟仍无结论，立即报告唯一阻塞点，由项目经理缩小范围或调整任务边界。
- 定向测试通过后不重复编写等价测试；每个小提交运行定向测试和生产构建，每个完整模块再运行 `scripts/verify-local.ps1`。
- 浏览器只验证页面行为；四个任务使用各自固定双标签并行验收。接口专测、代码定位和页面验收同时推进，不再设置全局浏览器排队。
- 项目经理每轮只做四件事：检查证据、判定通过/返工、串行发放 Git 时段、立即续派下一入口。

## 完成判定

全站只有同时满足以下条件才能标记完成：差异总表无“确认缺失/部分缺失/仍未证明”项；所有菜单入口与子页面逐项验收；全部权限角色、状态流转和失败阻断有证据；完整本地验证通过；临时数据零残留；工作区已提交且 `dev` 可追溯。服务器发布属于完成后的独立步骤，不纳入当前本地开发阶段。
