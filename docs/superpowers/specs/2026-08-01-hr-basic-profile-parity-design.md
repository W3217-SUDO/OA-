# 人事中心员工基本信息旧系统对齐设计

## 范围

本轮只处理“人事中心 → 员工新建 → 基本信息”页面。申浩旧系统页面为唯一行为基准；请假记录、事项记录、员工档案和提成设定仍保持独立子页面，后续分别核对。

## 目标行为

1. 保留开发页已有字段和扩展字段，不做删除性收敛；逐项确认旧系统字段是否缺失，缺失时补齐并保持旧系统字段语义。
2. 旧系统已有的 23 个核心字段必须继续存在：员工号、用户名、中文姓名、角色、密码、公司、部门、职务、数据级别、是否可用、账号类型、身份证号、手机、英语等级、专业学历、分机、籍贯、外语、毕业时间、社保情况、毕业学校、住址、身份证地址。
3. 新建空表单点击保存时，若旧系统的逐项弹窗行为属于当前功能缺口，则按旧系统顺序补齐；若仅为显示方式差异而不影响功能，则先记录，不删除现有扩展行为。
4. 旧系统已有的下拉字段和默认值继续保持：公司、数据级别、是否可用、账号类型及本轮已对齐的政治面貌、婚姻状况、生育状况、在职情况。

## 实现边界

- 仅修改本地 `dev` 工作副本，先通过单元测试、前端构建和本地浏览器双页面验证。
- 不创建、修改或删除旧系统业务数据；本地 SQLite 只使用本地开发数据。
- 不把密码、令牌或服务器私有配置写入仓库。
- 完成本轮后再决定是否提交并部署；服务器不执行构建。

## 验证

- 单元测试覆盖字段白名单、顺序、默认值和首个必填错误选择。
- `npm run build` 通过。
- 本地页面与旧系统同步验证字段、弹窗、取消/确认和四个子页入口未被破坏。
