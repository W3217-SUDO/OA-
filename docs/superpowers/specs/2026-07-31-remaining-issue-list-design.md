# 剩余问题清单修复设计

## 目标

完成《OA系统对接.xlsx》7 月 31 日工作表中尚未完成的条目；已发布的人事删除影响弹窗、沟通记录查看与列布局不重复实现。所有改动统一在测试服务器发布前完成验证。

## 业务依据与边界

- 工作簿每行、对应截图和归档旧系统源码共同构成验收依据；截图只说明入口和问题，不以像素复刻替代业务行为。
- 归档旧系统只读。编号、审批、权限和数据范围规则优先以其中的真实控制器、页面和数据关系为准；不存在旧规则的新需求采用最小、可审计、服务端强制的实现。
- 管理员保留全菜单、全数据和全字段权限；前端隐藏不替代服务端授权。
- 不创建补丁文件。每个可验收子项有定向审计/冒烟证据与 Git 提交；所有剩余项完成后统一发布到测试服务器。

## 实现分组

1. 人事：提成默认/编辑、账号可用、部门与角色权限分离、逾期扣款字段。
2. 用户中心：沟通记录附件上传、列表客户列、只读查看。
3. 客户：人员目录选择、编号、统计跳转、工具栏、编辑/删除、范围、回收、共享接收人、冲突查询。
4. 合同与客户门户：合同审批和无用印分流、客户账号激活生命周期。

## 技术设计

- 先用 CodeGraph 定位现有页面、FastAPI 路由、模型和调用链；仅在图谱未覆盖的旧系统源码中查找同一业务规则。
- 所有范围、删除、审批和激活限制由 API 执行；React 仅展示服务器允许的动作与明确错误。
- 附件采用沟通记录专用关系和受控下载/删除，不复用宽松的通用附件写入路径。
- 客户计数、关联跳转、人员候选和共享接收人由服务端返回稳定标识，页面使用只读详情预检后导航。
- 合同无用印路径保持审批记录，但进入合同只读详情而不是错误的审核页。

## 验收

每组均执行前端生产构建、Python 编译、菜单/客户端 API 审计及对应 API 冒烟；对截图入口进行浏览器验收。最后以独立 release 目录构建镜像，切换测试服务器 `current`，检查健康接口和服务状态。
