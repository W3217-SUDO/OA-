## 2. 新电脑恢复步骤

```powershell
git clone -o github https://github.com/W3217-SUDO/OA-.git
cd OA-
git remote add origin ssh://tencent/opt/sunhold-oa/git/sunhold-oa.git
git fetch --all --prune --tags
git switch dev
git pull --ff-only github dev
```

安装并确认：

- Git
- Node.js 22
- Python 3.12
- Docker Desktop（启用 WSL 2）
- PowerShell 7（推荐）

先阅读项目根目录的 `AGENTS.md`、`README.md`、`docs/迁移交接与当前状态.md` 和 `docs/功能实现清单.md`。不要把旧电脑的 `.env`、数据库、附件或 Docker 卷直接提交到 Git。

## 3. Git 远端与同步规则

```powershell
git remote -v
git fetch --all --prune --tags
git status --short
```

远端角色固定：

- `github`：GitHub 源码仓库，地址为 `https://github.com/W3217-SUDO/OA-.git`。
- `origin`：腾讯服务器上的 Git 裸仓库，地址为 `ssh://tencent/opt/sunhold-oa/git/sunhold-oa.git`。

正常同步顺序：

```powershell
git switch dev
git pull --ff-only github dev
git push origin dev
git push github dev
```

发布完成后，正式提交再按部署 Skill 的流程快进到 GitHub `main`。不要强制推送，不要创建长期 `release-*`、`deploy-*` 或 `ready-*` 分支。

### 测试服务器

- SSH 别名：`oa-test-tencent`
- 公网地址：`101.35.24.73`
- 用户：`root`

新电脑需要通过安全渠道取得对应私钥，并保存到本机用户私有 SSH 目录，例如：

```text
~/.ssh/tencent_lighthouse_150_158_3_104_ed25519
```

在 `~/.ssh/config` 中配置别名：

```sshconfig
Host baota-lighthouse
    HostName 150.158.3.104
    User root
    IdentityFile ~/.ssh/tencent_lighthouse_150_158_3_104_ed25519
    IdentitiesOnly yes
    ConnectTimeout 10
    ConnectionAttempts 3
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

连接检查：

```powershell
ssh -o BatchMode=yes -o ConnectTimeout=10 baota-lighthouse "echo SSH_OK; hostname; whoami; free -h; df -hT /"
```

私钥内容、云 API Secret、服务器密码不写入本文件、不提交 Git、不放入普通压缩包。若旧电脑上的私钥已无法安全转移，应在腾讯云控制台重新生成密钥并更新服务器授权，而不是复制聊天记录中的密钥。

## 6. 环境变量与凭据

仓库只提交示例配置：

- `.env.example`
- `.env.production.example`

实际运行时需要在本机或服务器私有文件中配置：

- `SECRET_KEY`
- `POSTGRES_PASSWORD`
- `MINIO_ROOT_PASSWORD`
- 钉钉 `DINGTALK_*` 凭据
- Dify 或模型服务 API Key
- 任何云厂商 Access Key、Secret Key、Token

服务器生产配置位置以服务器当前服务配置为准，优先核对：

```text
/opt/sunhold-oa/private/.env.production
```

新电脑开发时复制 `.env.example` 为本地 `.env`，只填本地开发值；不要把服务器 `.env.production` 下载到项目目录。

## 7. OSS / 对象存储状态

当前已核对的跟踪代码没有发现可直接提交的外部 OSS/COS 公网地址。应用当前配置的是 MinIO，对象存储服务名为：

```text
MINIO_ENDPOINT=minio:9000
```

附件主要保存在 Docker 的 `uploads_data` 数据卷中。生产环境的对象存储地址、桶名、访问密钥应以服务器私有环境变量和腾讯云控制台为准。

接手时在安全凭据管理器中补齐以下信息，不写进 Git：

```text
OBJECT_STORAGE_ENDPOINT=
OBJECT_STORAGE_BUCKET=
OBJECT_STORAGE_REGION=
OBJECT_STORAGE_PUBLIC_BASE_URL=
OBJECT_STORAGE_ACCESS_KEY_ID=
OBJECT_STORAGE_SECRET_ACCESS_KEY=
```

如果生产环境实际使用腾讯云 COS，请记录 COS 控制台链接和桶名到企业密码管理器的项目条目；如果仍使用服务器 MinIO，则记录 MinIO 内网地址、桶名和对应凭据。当前代码检索未发现已配置的 OSS/COS 桶链接，不能凭空填写。
