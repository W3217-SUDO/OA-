# 8.27 工作表第 3 行本地验收记录

## 根因与修复

- 控制台原先使用与费用查询不同的统计口径，点击卡片后也没有携带旧系统的“本人 + 未缴官费”隐藏条件，因此卡片数与列表总数不一致。
- 费用查询的人名展示在无法解析人员时使用了“姓名待维护”伪姓名。
- 统一由后端费用查询产生控制台待缴官费指标，并把 `{ scope: "mine", unpaid_official: true }` 作为卡片目标查询；前端进入费用查询、刷新和点击“清空”时都保留这两个隐藏条件。
- 人员展示只采用可解析的真实显示名；未填写或无法解析时显示横杠，不再构造“姓名待维护”。
- 官费已付金额同时兼容财务交易和费用记录本身的已付金额，避免已支付费用被错误计入未缴集合。

## 旧系统目标核对

- `DashboardController.cs` 使用 `PageId_5001010002`、当前登录用户和 `HasUnPaidOfficeFee=true` 调用费用查询，并用同一查询的 `TotalCount` 展示卡片。
- 控制台卡片打开 `/FAM/CaseFee/CaseFeeList`；`CaseFeeController.cs` 对该 PageId 再次固定当前登录用户和未缴官费条件。
- 旧费用列表对未填写人员保持空白，不使用“姓名待维护”。

## 隔离测试数据

本地副本数据库包含 5 条专用费用记录：当前用户未缴官费 2 条（其中一案有开庭律师“范文玲”、一案未填）、当前用户已缴官费 1 条、当前用户非官费 1 条、其他用户未缴官费 1 条。预期且实际只返回前两条，总金额 800.00。该数据库只用于 127.0.0.1 本地验收，验收后已删除；没有连接或写入线上数据库。
