# 旧数据库全表结构审计 v1.0.160

## 基准与范围

- 唯一结构基准：本机只读 SQL Server `PRD_CRM_GD_20200211`，对应旧系统 `http://localhost:8091/Console/Index`。
- 旧库共 239 张 `dbo` 表、3951 个字段、206 个主键、177 个 identity 字段、104 个非主键索引；旧库没有外键，业务关联为编号和 ID 软关联。
- 线上候选 v1.0.159 原有 67 张 PostgreSQL 表，其中仅 18 张为旧系统同名兼容表，缺少 221 张旧表。

## v1.0.160 整改

- `app/legacy_schema_manifest.json` 固化全部旧表字段、类型、长度、精度、可空性、identity、复合主键和索引定义。
- FastAPI 启动时仅新增缺失旧表，不删除或重建已有业务表。
- 修正 `FCM_Contract_File`：旧库主键是 `FileGuid`，`FileId` 为 bigint identity；此前候选版本错误地以 `FileId` 为主键。
- 现有 18 张同步投影的 `char(1)`、`bigint`、`varchar(8000)` 等类型与旧库一致，并在迁移前检查现有值是否可安全转换。
- 恢复旧索引并移除同名投影表上的临时索引。SQL Server 可在索引中包含超过 32 个列，PostgreSQL 上限为 32；迁移保留完整键列并截取可容纳的 INCLUDE 列，原始完整定义仍保存在清单中。
