# 逐动作交替对照验收规则

## 当前目标

以申浩旧系统为只读业务基准，在本地 `dev` 分支完成 OA 全站功能对齐。主会话只负责项目管理、任务拆分、监督、验收和串行 Git 提交；独立开发任务负责双站对照、实现、测试和数据清理。全部功能在本地验收完成后，才统一部署测试服务器。

## 强制执行顺序

每个菜单、页面、按钮、字段、弹窗、跳转、筛选、分页、上传下载、导入导出、权限拦截、状态流转、审批和失败路径都必须按以下顺序执行：

1. 在申浩旧系统打开目标页面并执行一个只读动作。
2. 立即切换到本地系统，在对应页面执行同一个动作。
3. 逐项比较出现条件、字段、按钮、弹窗、跳转目标、提示、权限、状态变化和后续关联页面。
4. 发现本地缺失或行为不同，立即在本地完成最小修复、定向测试，并重新操作两个系统复验。
5. 当前动作一致后，才能回到旧系统执行下一个动作。

禁止先完整盘点旧系统、再单独检查本地系统；禁止只看菜单、截图、源码或测试用例后宣称对齐。

## 旧系统只读边界

- 旧系统允许打开菜单、页面、详情、表单、弹窗、下拉框、分页和筛选入口。
- 涉及新增、保存、修改、审批、上传、删除或状态流转时，只检查页面和确认弹窗，随后取消，不提交写操作。
- 本地系统使用 `CODEX-*` 前缀测试数据完成真实成功与失败闭环。
- 只删除本任务创建的测试数据、附件和临时文件，不得删除既有数据。

## 每个动作的验收证据

每一步必须成对记录：

- 申浩旧系统的实际 URL、页面名称、执行动作和结果。
- 本地系统的实际 URL、页面名称、同一动作和结果。
- 两边的明确差异；若无差异，也要说明实际核对了什么。
- 修复文件、定向测试和修复后的双站复验结果。
- 测试数据、数据库记录、附件和临时文件的精确清理结果。

缺少任一侧实际点击证据，或旧站停留在无关页面/iframe，均不得通过验收。

## 提交与部署

- 所有修改仅进入 `dev` 分支。
- 每个最小业务闭环完成后，由主会话复核差异、测试、构建和清理，再按明确文件串行 Git 提交。
- 本地全站验收完成前不部署；全部完成后统一部署测试服务器并再次验收。
