# 客户列表最小闭环验收（2026-08-01）

## 双页面证据

- 旧系统（只读）：`https://sh.021ipr.com/Console/Index`。从系统导航展开“客户管理”，进入“我的客户”；页面标题显示“我的客户”，正文可见“搜索”、当前用户“管理者”和客户管理菜单。旧站包含 iframe，尝试读取列表 iframe 时发生超时，因此未执行任何写入操作。
- 本地 dev：`http://127.0.0.1:5173/?page=customer-mine`。最新 DOM 显示“客户列表”、筛选字段“客户名称 / 客户/当事人 / 客户管理人”、按钮“查询 / 重置”、客户表格列、行操作“客户查看 / 更多操作”和分页“共有1条，每页显示15条”。

## 差异与修复

旧系统对照操作要求列表筛选区提供搜索/重置能力；本地列表原先只有“查询”，缺少“重置”。在本地补充“重置”按钮：清空客户名称、客户类型、管理人筛选，清空选中行，并在当前页重新加载或回到第 1 页。旧系统保持只读，本轮未创建或修改客户数据。

## 复验

本地页面重新加载后 DOM 可见“查询”和“重置”，并保留客户列表、表格与分页；旧页面 URL/标题仍为上述只读客户列表。浏览器出现旧站 iframe 读取超时后已废弃旧对象并重新打开双页面。

追加复验：在最新本地页面先输入 `CODEX-CASE-B-1785595432091` 并点击“查询”，列表收窄为 1 条；再点击“重置”，输入框恢复为空、页码为 `1`，列表恢复为 2 条且分页摘要恢复。重置后选中项计数为 `0`。本地请求由显式 `{keyword:"", customerType:..., managerKeyword:"", page:1}` 参数触发，避免 React 状态尚未提交时带入旧筛选。

继续入口复验：在本地列表点击 `CODEX-CASE-B-1785595432091-CUSTOMER`，进入“我的客户”查看页，实际回显客户名称、客户编码、客户类型、建档日期、管理人及“联系人/事项记录/客户文档”标签；查看表单控件均为禁用态，未执行写入。旧站新页面仍为“我的客户”只读页，DOM 可见客户管理菜单与列表 iframe，但 iframe 内容读取受限，未对旧站执行任何点击写操作。

## 数据清理

本轮没有创建客户测试数据；仅查询本地数据库确认不存在本线程 `CODEX-HR-LIST-*` 客户记录，因此无删除动作。
