# UI 字段 ↔ MCP 接口对照表

- 步骤编号对应 `01-PPT业务清单.md`。
- **UI 字段**写法：`新系统表单标签=参数名`，`*` 为必填。标签取自 `apps/admin-web/src` 的实际表单（PPT 截图是旧申浩界面，名称基本一致，差异处已注明）。
- **接口**是 OA MCP 目录（由后端实际路由自动生成，共 878 个工具）里的工具名与路径；`body.data.x` 表示字段放在请求体 `data` 对象里。
- **结论**：✅ 对上；⚠️ 对上但有坑（见末尾“缺口清单”编号）；❌ 缺接口或不开放。

## 缺口清单（对不上 / 缺接口）

| 编号 | 问题 | 影响 | 业务工具里的处理 |
|---|---|---|---|
| G1 | 合同、线索、客户编辑的大部分 UI 字段放在请求体 `data` 里，接口参数定义里 `data` 是自由对象，没列出键名 | 智能体只看接口定义猜不出“合同类别=data.type”“销售渠道=data.sales_channel” | 业务工具把这些字段展开成有中文说明的具名参数，内部再组装 `data` |
| G2 | 合同新建用 `data.type`，合同变更用顶层 `contract_type`；同一个“合同类别”两个名字 | 容易填错 | 业务工具统一叫 `contract_type`，内部按接口转换 |
| G3 | 新建调查任务页面“授权范围=region、授权区域=authorization_scope”，名字和含义交叉 | 容易填反 | 业务工具参数用 `investigation_region`（调查/授权范围）和 `authorization_scope`，说明写清 |
| G4 | 所有上传都要先拿到附件 ID（MCP：先调 `/api/v1/agent-tools/upload` 上传得到 attachment_id） | 一步做不完 | 业务工具接受 `attachment_ids`，内部挂到对应记录 |
| G5 | 客户服务端开通（账号密码）不在 MCP 目录 | 智能体不能开通 | 维持不开放（涉及密码），工具里提示到网页办理 |
| G6 | 新建案件一个页面，后端是 建案 + 当事人 + 司法信息 三个接口 | 需要串联 | 业务工具“从合同新建案件”内部依次调用 |
| G7 | 审批、盖章、付款核销、开票作废、退费到账属“不可撤回”，MCP 只生成待确认请求 | 智能体不能直接批 | 业务工具照样走同一通道，返回待确认链接，须本人在网页确认 |
