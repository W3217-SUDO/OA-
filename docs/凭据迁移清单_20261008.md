# OA 系统凭据迁移清单

更新时间：2026-10-08（中国标准时间）

本文只记录凭据类型、来源和迁移位置，不记录任何密钥值。迁移时使用企业密码管理器或受控加密介质，禁止把密钥写入 Git、Markdown、Issue、聊天记录或普通压缩包。

## 一、迁移原则

- 新电脑先完成代码拉取，再单独配置本机凭据。
- 生产凭据只保存在服务器私有环境文件或密码管理器中。
- 开发、测试、生产使用不同的密钥；不要复用生产密钥。
- 发现密钥曾出现在聊天、截图、日志或 Git 历史中时，立即轮换并撤销旧值。
- 迁移完成后只验证“能否连接”和“权限是否正确”，不把凭据打印到终端或日志。

## 二、凭据清单

| 凭据类别 | 需要迁移的项目 | 新电脑/服务器保存位置 | 验证方式 |
| --- | --- | --- | --- |
| 腾讯生产 SSH | 生产服务器私钥、主机指纹、SSH 别名 `baota-lighthouse` | 新电脑用户私有 SSH 目录和 `~/.ssh/config` | `ssh -o BatchMode=yes baota-lighthouse "whoami"` |
| 腾讯测试 SSH | 测试服务器私钥、主机指纹、SSH 别名 `oa-test-tencent` | 新电脑用户私有 SSH 目录和 `~/.ssh/config` | 只读执行 `hostname`、`whoami`、磁盘检查 |
| GitHub | GitHub 登录凭据或 SSH key、仓库写入权限 | Git Credential Manager 或用户私有 SSH 配置 | `git ls-remote github refs/heads/dev` |
| 腾讯 Git 远端 | `origin` 的 SSH 访问权限 | Git SSH 配置，不写入仓库 | `git ls-remote origin refs/heads/dev` |
| 生产应用 | `SECRET_KEY`、数据库密码、Redis 密码、MinIO 管理密码 | `/opt/sunhold-oa/private/.env.production`（以服务器实际服务配置为准） | 服务健康检查，不输出变量值 |
| 本地开发 | 本地数据库、Redis、MinIO 的开发密码 | 项目目录未跟踪的 `.env` | `docker compose ps` 与本地 `/health` |
| 钉钉 | `DINGTALK_CORP_ID`、`DINGTALK_AGENT_ID`、`DINGTALK_APP_KEY`、`DINGTALK_APP_SECRET` | 私有环境变量或密码管理器 | 调用最小权限接口，检查返回状态 |
| Dify/模型服务 | Base URL、API Key、模型名 | 私有环境变量或密码管理器 | 使用健康检查或最小测试请求 |
| MinIO / OSS / COS | Endpoint、Bucket、Region、Access Key ID、Secret Access Key | 服务器私有环境变量或密码管理器 | 上传/读取一个非业务测试对象后删除 |

## 四、新电脑配置顺序

1. 安装 Git、Node.js 22、Python 3.12、Docker Desktop。
2. 配置 GitHub 凭据，克隆仓库并切换到 `dev`。
3. 配置腾讯服务器 SSH 别名，先执行只读连接检查。
4. 复制 `.env.example` 为本地 `.env`，填入开发环境专用值。
5. 仅在需要部署时，通过受控方式读取服务器生产环境配置；不要把生产配置复制到工作树。
6. 配置钉钉、Dify/模型和对象存储凭据。
7. 启动服务并执行健康检查，确认日志中没有打印 Secret、Token 或密码。
