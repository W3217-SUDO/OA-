# 新电脑恢复与继续开发

## 一、准备环境

1. Windows 10/11 64 位，BIOS 中开启 SVM/VT-x。
2. 安装并启动 Docker Desktop，选择 WSL 2 后端。
3. 安装 Codex Desktop；Node/Python 可由项目脚本安装，也可使用本机版本。
4. 将整个迁移包复制到仅当前用户可访问的磁盘目录。

## 二、恢复顺序

1. 解压迁移包（如果拿到的是 ZIP）。
2. 进入迁移包根目录，以 PowerShell 运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\RESTORE_ALL.ps1 -TargetDirectory 'C:\Users\你的用户名\Desktop\系统重构'
   ```

3. 脚本会复制源码、导入 Docker 镜像、创建容器和卷、恢复 PostgreSQL/Redis/MinIO/附件，再启动六个服务。
4. 打开 `http://127.0.0.1/`；本地开发初始账号为 `admin`，初始密码见项目 README。上线前必须修改。
5. 运行验收：

   ```powershell
   cd 'C:\Users\你的用户名\Desktop\系统重构'
   powershell -ExecutionPolicy Bypass -File .\scripts\verify-local.ps1
   docker compose ps
   ```

## 三、让新电脑 Codex 接手

向新电脑 Codex 发送：

> 请先完整阅读项目根目录 AGENTS.md、README.md、docs/迁移交接与当前状态.md、docs/功能实现清单.md。先运行 Docker 健康检查和验收脚本，不要重做已完成工作。继续以原系统只读对照，逐页验证尚未证明的视觉、字段、按钮、弹窗和权限；管理员必须保持最高权限。

## 四、恢复失败时

- Docker 未启动：先打开 Docker Desktop，等待状态显示 Running。
- 80/8000/9001 端口被占用：停止占用端口的软件后重试。
- 镜像导入慢：属于正常现象，不要中断 `docker load`。
- PostgreSQL 恢复失败：不要删除迁移包；查看 `migration-manifest.json` 和 `data/postgres`，再按 `deploy/restore.sh` 的逻辑人工恢复。
- 验收失败：保留日志，不要清空卷或重建数据；先定位失败步骤。

## 五、安全要求

- 迁移包包含业务数据库和附件，按保密资料管理，不上传网盘公共链接或代码托管平台。
- `docker-images.tar` 可以重新构建，但 `data/` 不可丢失。
- 原系统密码、Dify Key、生产密钥不进入普通文档或 Git。
