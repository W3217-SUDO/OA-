# OA 全套企业级整改计划与进度

## 用户目标与边界

用户要求：最新代码归类清楚，前后端都整改为便于维护、升级、解耦和扩展的代码；清理没有必要的测试和历史代码；生产源码、构建与部署包严格隔离测试；全部检查无问题后统一提交并推送 Git。2026-10-01 最新要求明确暂时排除权限问题。

本计划覆盖 `apps/admin-web`、`apps/api-server`、`apps/deepseek-harness-host` 及支撑它们的构建、验证、配置与交付脚本。既有业务行为和接口保持稳定。角色、权限矩阵、授权范围与身份解析不作为本轮整改对象。权威基线已有的权限修复原样保留。此次不部署、不修改线上业务数据库、不运行浏览器自动化。

“完成”必须有实际代码和可重复验证证据。减少文件行数、移动代码、静态正则通过或生产构建成功，均不能单独证明全套整改完成。

## 基线与工作方式

- 2026-10-01 权威基线：`a2fb465d787bfcb50d493ece69b95990b69faff9`，版本 `v1.1.223`，腾讯 `dev` 与 GitHub `dev/main` 同提交。
- 本地原有 30 项受跟踪改动、7 个新增文件已逐文件备份、三方合并并校验，更新基线没有新增提交。
- 当前主工作树：`最新代码`。并行改动使用独立工作树、测试数据库、附件目录、端口和证据目录，由主任务逐项审核与集成。
- 所有必要测试留在独立测试目录。保留有效运行时测试；删除失效、重复或无意义测试必须列明依据，不能按文件数量批量删除。
- 每个工作包遵循：理解实现和调用链 → 记录具体问题和接口边界 → 最小范围整改 → 验证成功、失败及持久化 → 保存结果和清理临时数据。
