更新时间：2026-07-22

本清单用于按旧 OA 源码逐项比对新系统前端页面跳转、按钮关联和业务承载页面。旧系统源码只作为只读证据，不向旧系统写入数据。

## 2026-07-22 第一批源码对照结论

### 已修复：跨模块案号入口应进入完整案件信息

旧系统中案号/案件编号承担“打开案件信息工作台”的入口含义。案件详情页不是任务创建页，也不是仅有少量字段的简化弹窗；它包含基本信息、文档、费用、内部结算、案件提醒、案件日志、系统日志、案件任务、客户任务等关联区域。

本轮已在新系统建立统一跳转通道：

- `caseDetailNavigation.ts`：跨模块记录目标案号。
- `CaseCenterPage.tsx`：案件中心加载后消费目标案号，自动打开完整案件详情工作台；如果第一页未命中，会按案号再查询一次，避免大数据量下找不到。
- `FinanceCenterPage.tsx`：财务中心中“案号/案件编号”入口不再只跳到公司案件列表，而是打开对应案件详情。
- `InvestigationCenterPage.tsx`：调查线索、公证审核中的关联案件入口改为进入完整案件详情；没有导航能力时保留原本地弹窗兜底。
- `TaskCenterPage.tsx`：任务列表和未读任务列表中的案号改为打开完整案件详情；“案件任务/案件日志”按钮仍保持原含义。

### 已发现但未全部闭环：旧案件列表更多操作比当前更丰富

旧系统 `Areas\Legal\Views\CaseArchive\PendingList.cshtml`、`RejectedList.cshtml` 等列表中可见以下动作：

- 上传案件文档
- 新增案件费用：律所费用、非律所费用、提成费用
- 新增内部费用
- 批量修改参与人、案件任务等
- 生成授权委托书
- 生成律所函
- 生成身份证明
- 生成结算提成表

当前系统已有部分能力，但还需要继续逐项确认入口位置、权限、状态限制、生成文件、落库记录和后续页面同步，不能只按“有类似按钮”认定完成。

### 已发现但未全部闭环：案件详情内部关联还需继续对齐

旧系统案件详情中客户、合同、当事人、任务、文档等对象存在互相跳转，例如客户查看、合同查看、任务查看。当前案件详情工作台已有基础布局和真实数据接口，但仍需继续把详情内部每个编号/按钮与旧系统源码逐项映射。

## 下一批建议对照范围

1. 案件中心：列表“更多操作”逐按钮对照旧源码，补齐文件生成、上传、费用、内部费用、批量修改、案件日志/任务入口。
2. 案件详情：基本信息区中的客户、合同、当事人、法院、律师、文档树、日志、任务、费用标签页逐项验收。
3. 合同中心：合同号、客户号、案件号的互跳关系，对照旧合同页面与当前合同向导/合同详情。
4. 财务中心：费用单、请款单、请票单、付款包、归档结算与案件详情之间的跳转和状态同步。
5. 调查/公证：线索转案件、公证书登记、证据材料、案件编号入口和文件归档位置。
