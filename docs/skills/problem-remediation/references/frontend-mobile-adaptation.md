# 前端手机适配检查

适用于每次 OA 前端新增、整改、返工和样式修改。保留本次业务逻辑、权限和数据范围，只调整受影响的呈现与交互。

## 修改前

- 根据用户截图确认手机入口、页面区域、横竖屏状态与异常：桌面列数是否仍在手机使用，文字是否被挤成单字竖排，数字、图标、日期和操作按钮是否越界。
- 追踪 viewport 配置、页面宽度、父容器最小宽度、滚动区域、样式导入顺序、媒体查询、容器查询与选择器覆盖。区分“写了窄屏规则”和“实际目标设备命中了窄屏规则”。
- 核对页面所用的现有移动导航、底部安全区和断点，不新建另一套全局手机布局；明确本次需要改动的共享选择器与受影响入口。

## 实现要求

- 窄屏卡片和表格必须按可用空间重排，不能把桌面的四列、五列或固定列宽直接压进手机。使用当前目标 WebView 能实际生效的基础布局规则；容器查询可用于局部增强，手机核心重排仍须有明确的屏幕宽度规则。
- 标签保持横向阅读，允许自然换行；长姓名、公司名、案号和金额采用适合该字段的换行、截断或局部横向滚动，不能重叠，也不能通过缩到不可读字号掩盖布局问题。
- 数字与单位、右侧箭头必须留出各自宽度。图标使用统一尺寸，与标签第一行或按钮中心对齐；图标和文字容器均应明确最小宽度与收缩关系。
- 可点击区域至少 44 × 44 CSS 像素。需要输入的页面检查输入框、软键盘、发送和取消入口；不能让弹层、底部导航或安全区盖住当前操作。
- 列表和详情的最后一项必须可以滚动到完整可见位置。保留加载、空数据、错误、禁用和权限不足状态，不能通过隐藏真实内容来适配。

## 修改后核验

- 至少核对 320、375、390、414 CSS 像素手机宽度，以及 768 像素和页面现有桌面断点附近的布局；横屏按该页面实际可用宽度核对。只检查本次受影响的区域及共享规则。
- 检查实际生产构建中的 CSS 条件、覆盖顺序和布局结果，不把源码里匹配到一条 `@media` 或 `@container` 作为唯一证据。核心手机布局应在目标容器查询不生效时仍保持正确列数与边界。
- 使用项目已有的定向核验工具或样式解析检查，并完成生产构建。用户未要求新测试脚本时不新增专门测试脚本；需要测试代码时放入既有独立测试目录，不进入生产源码和运行包。
- 记录适用入口、宽度范围、长文本与大数字边界、图标/按钮对齐、底部遮挡检查、构建结果和证据路径。自动化样式核验只能证明对应检查，不等于真实手机页面验收。
- 默认由用户进行浏览器和真机页面验收；只有用户明确授权当前问题的浏览器自动化时才控制浏览器，仍禁止使用 Codex 内置 `iab`。
- 用户反馈手机未适配时，立即把本任务记录为返工，先审计上次未生效的样式与遗漏的入口，再修复、重新构建并按正常发布流程上线。
