# OA 问题处理

本 skill 适用于问题表、钉钉在线表格、截图返工和客户验收问题。每一行是一个独立问题容器；一行可以包含多个子问题、多个业务动作和多张截图。

详细的截图清单、证据锁、VibeHub、批次门禁、手机适配和发布编排规则见 [execution-details.md](references/execution-details.md)。本页是所有会话必须先执行的短流程。

## 1. 先分流：旧系统对照还是新增需求

- 行内有旧系统截图，或文字出现“参考旧系统、按旧系统、与原系统一致、原系统模式”等要求：按旧系统整改。必须追踪旧页面、源码、接口/控制器、服务、数据表、权限、状态和下游结果；旧系统只读。
- 没有旧系统截图，文字也没有旧系统对照要求，并明确提出旧系统不存在的新规则、新流程或新能力：按新增需求处理。旧系统代码不适用，文档写明“新增需求，旧系统代码不适用”，不得强行寻找相近旧实现。
- 无法确认分流：记为“证据不足/待核实”，先停在定位阶段，不改代码、不写入测试数据、不部署。

## 2. 一行拆子问题，一张图一张图读取

1. 从线上工作表完整读取该行所有列、原文、补充、返工、状态、批注、链接和图片锚点。
2. 保留“问题”单元格逐字原文，不润色、不缩写、不改语义。
3. 先列出本行子问题清单，再建立：
   `原文片段 -> 子问题 -> 一张或多张相关截图 -> 旧系统/新增需求证据 -> 新系统根因 -> 修改/验收`
4. 每次只输入本行完整原文和一张当前截图。记录页面/菜单/标签页/弹窗、字段、数据、按钮、红字、红框、状态、证据角色和待核实项；记录落盘后才能看下一张。
5. 同一张图可以支撑多个子问题，同一子问题也可以需要多张图；不得按图片数量猜问题数量，不能用 OCR 或“已看过”代替视觉记录。

## 3. 每行必须有独立 Markdown 定位文档

文档至少包含：

- 工作表、行号、扫描列和逐列原文；
- 子问题清单、全部图片 ID/锚点/列、页面身份和证据角色；
- 旧系统真实行为，或“新增需求，旧系统代码不适用”；
- 新系统页面、前端、后端、权限、状态、数据库和关联链路；
- 原文片段到代码/接口/数据的追踪表；
- 修改文件、失败路径、测试数据、部署版本；
- 接口状态码/响应/数据库回读、浏览器结果、导出文件回读和清理结果。

没有文档、图片未读取、证据角色不确定或原文片段未映射时，该行未完成。

## 4. 定位确认与实施门禁

- 先完成本批所有行的独立文档和整批汇总，再等待用户确认定位；用户明确要求“定位后直接修改”时才可跳过等待，但不能跳过文档。
- 定位确认后一次性实施整批，不能边看边临时改。旧系统截图只读，新系统才可修改。
- 测试数据使用唯一 `CODEX-*` 标识；保存后必须接口/数据库回读，测试结束按父子关系精确删除并再次查询零残留。

## 5. 验收、回写和部署

- 接口问题：验证成功和失败状态码、响应、数据库结果、权限和异常路径。
- 页面问题：复现同一入口和同一操作路径；涉及导出时生成真实文件并回读内容。
- 前端改动：按项目要求完成类型检查、生产构建和必要的浏览器验收；手机适配按细则执行。
- 部署前必须通过本地检查和 `oa-fast-deploy` 门禁；部署回执记录版本、提交、服务、健康检查和目标入口。
- `G/H/I` 只写摘要和状态，不能替代 Markdown。只有原文、所有子问题、所有截图、接口/数据库、浏览器/文件回读、清理和部署证据全部闭环，才允许写 `1/已验收`。
