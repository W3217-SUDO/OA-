## 3. 旧系统实现
- 入口、角色和数据状态：旧系统 `Legal/Case/CaseController.CaseView` 打开案件详情；按案件类型渲染 `CivilDisputeCase_View.cshtml` 等子模板。
- 页面载体和布局：`Areas/Legal/Views/Case/View.cshtml` 的案件信息下方依次渲染类型区块；民事案件的法院信息在存在一审、二审、执行或再审法院名称时显示，归档信息在归档状态为 P/E/R 时显示。
- 操作步骤与按钮行为：民事案件的法院信息和归档信息标题右侧使用 `spanCaseCourt` 折叠控件；初始为 `icon-up`，点击后隐藏区块并切换为 `icon-down`，再次点击恢复显示。
- 字段默认值、展示和校验：法院区块只显示实际有法院名称的阶段行；归档区块只在归档状态满足条件时显示，归档信息默认展开。
- 状态流转及下游结果：折叠只改变当前详情视图，不写入案件或日志数据；案件信息、下方功能页签和日志数据不受影响。
- 数据表、字段及关联：案件详情来自案件业务记录的 `data` 字段；法院字段包括一审、二审、执行、再审法院及其案号/法庭/日期；归档字段包括归档类型、提交/审核信息及归档号。
- 采用证据：
  - `legacy-gdcrm-101-local-20260812/source/GD.CRM.WEB.VIP/Areas/Legal/Views/Case/View.cshtml`
  - `legacy-gdcrm-101-local-20260812/source/GD.CRM.WEB.VIP/Areas/Legal/Views/Case/PartialView/CivilDisputeCase/CivilDisputeCase_View.cshtml`
  - `legacy-gdcrm-101-local-20260812/source/GD.CRM.WEB.VIP/Scripts/Legal/Case/Legal.Case.Invoke.js:398-410`
  - 旧系统截图图 3、图 4。

## 4. 新系统当前实现
### 前端
- 已完成：法院信息、归档信息使用本地展开状态；标题右侧补充上下箭头按钮、`aria-expanded`、`aria-controls` 和提示文字；切换案件时恢复默认展开。合并来源递归渲染使用 `useId` 生成独立控件标识。
- 已完成：再审法院、法庭、案号、立案/开庭/判决日期接入详情展示与可见性判断。
- 页面和入口：`apps/admin-web/src/legal/CaseCenterPage.tsx` 的案件详情抽屉，顶部由 `CaseDetailHeader` 渲染。
- 文件：`apps/admin-web/src/legal/CaseDetail/CaseDetailHeader.tsx`、`apps/admin-web/src/caseDetailSectionVisibility.ts`、`apps/admin-web/src/case-center.css`。
- 组件/函数：`CaseDetailHeader`、`getCaseDetailSectionVisibility`。
- 状态、事件和 API 调用：可见性函数按法院/归档字段判断是否渲染；折叠状态由 `CaseDetailHeader` 本地维护，不新增 API 或持久化。
- 当前行为形成原因：此前“隐藏空法院和归档区块”的整改只保留了条件渲染，未把旧系统的标题折叠交互迁移到新组件；法院可见性字段也未覆盖再审字段。

### 后端
- 文件：不涉及。
- 路由：不涉及，现有案件详情接口已返回用于展示的案件 `data`。
- 服务/权限/校验函数：不涉及，折叠是纯前端视图状态，沿用既有权限和数据范围。
- 持久化及下游逻辑：不涉及，展开/收起不产生写入。
- 当前行为形成原因：后端不是缺陷来源。

### 数据库
- 表：不涉及数据库结构或数据修补。
- 主键/软关联字段：不涉及。
- 状态/权限字段：沿用案件状态和现有归档字段。
- 查询或写入关系：不改变查询与写入关系。
- 历史数据兼容：通过既有字段别名读取一审、二审、执行、再审信息。
