# OA 全站源码能力对齐台账

更新时间：2026-08-02

## 当前工作方式

- 业务基准：`旧系统归档源码/SH.CRM.WEB`。
- 定位顺序：旧源码仓库存在 `.codegraph`，先用 CodeGraph，再读取必要的 Controller、View、JavaScript、DTO 和权限代码。
- 对齐对象：旧源码路由、字段、校验、权限、状态、失败文案、文件处理、分页以及跨模块参数和回写。
- 不再执行网站逐动作比对、登录、验证码、旧站造数或清理。
- 本地已有而旧源码没有的额外能力保留；旧源码存在而本地缺失的能力必须补齐。
- 每批处理 10–20 个相关缺口，任务只跑定向测试和类型检查；主会话统一运行生产构建、Python 编译和 Git 提交。
- 所有改动只进入 `dev`；禁止 `git add .`，全站源码矩阵清零前禁止部署。

## 后端串行补齐队列

由于 FastAPI 路由主要集中在 `apps/api-server/app/main.py`，以下后端修改必须按模块串行，避免六线并发覆盖：

1. 系统：组织列表 `page/page_size` 与分页元数据；动态菜单/动作权限树读取及保存接口。
2. 财务：普通付款撤销/回滚、合同付款复合键精确查询、流水与付款包分页、结算数据库层分页、PageId 权限映射。
3. 用印：默认15条、附件批量删除、多记录盖章/标记接口及契约测试。
4. 合同：状态专用列表、服务端查询与六档分页、附件审计、客户关联合同专用查询、旧错误协议决策。
5. 客户：14项列表汇总、共享对象读取、默认/有效联系人动作、customerGuid 文件兼容、客户事件、PATCH 响应字段过滤。
6. 案件回溯：合并费用/文档迁移、线索批量原子事务、旧阶段父子过滤和通用批量阶段语义统一。

## 完成判定

只有以下条件同时满足，才能将全站目标标记完成：

1. 旧源码可达能力全部进入模块矩阵，每项都有 Controller/Service/DTO/Model/View/JS 证据和本地映射。
2. React 页面、FastAPI 路由/DTO、数据库字段、权限、事务、状态回写与审计缺口全部实现；本地额外能力未被删除。
3. 每项有独立前端测试和后端契约或稳定矩阵断言，模块回归、完整构建和 Python 编译全部通过。
4. 共享工作树没有未审计业务改动，全部提交只位于 `dev`。
5. 最后统一部署测试服务器并完成验收。
