## 当前工作方式

- 业务基准：`旧系统归档源码/SH.CRM.WEB`。
- 定位顺序：旧源码仓库存在 `.codegraph`，先用 CodeGraph，再读取必要的 Controller、View、JavaScript、DTO 和权限代码。
- 对齐对象：旧源码路由、字段、校验、权限、状态、失败文案、文件处理、分页以及跨模块参数和回写。
- 不再执行网站逐动作比对、登录、验证码、旧站造数或清理。
- 本地已有而旧源码没有的额外能力保留；旧源码存在而本地缺失的能力必须补齐。
- 每批处理 10–20 个相关缺口，任务只跑定向测试和类型检查；主会话统一运行生产构建、Python 编译和 Git 提交。
- 所有改动只进入 `dev`；禁止 `git add .`，全站源码矩阵清零前禁止部署。

## 完成判定

只有以下条件同时满足，才能将全站目标标记完成：

1. 旧源码可达能力全部进入模块矩阵，每项都有源码位置和本地映射。
2. 所有本地缺口已实现，本地额外能力未被删除。
3. 每项有独立测试或稳定矩阵断言，模块回归、完整构建和 Python 编译全部通过。
4. 共享工作树没有未审计业务改动，全部提交只位于 `dev`。
5. 最后统一部署测试服务器并完成验收。
