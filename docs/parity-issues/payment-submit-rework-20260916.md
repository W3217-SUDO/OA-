## 旧系统证据

## 新系统与只读数据核实
PaymentApplicationPage 优先使用 data.payment_status，忽略主状态；只读线上目标记录确认主状态已审批，JSON付款状态仍待审批，没有付款包。该分支因此显示普通打印。

第二层遗漏：FinanceCenterView 及 payment_workflow.payment_record 均硬编码 admin/manager/auditor。截图账号基础角色为 user，但有效菜单包含 finance-payment-waiting、finance-payment-print、finance-payment-writeoff。不得只加按钮后让接口继续403；也不能直接允许所有普通用户操作。

表为 business_records；以记录 id 关联付款包 payment_package_id/fee_ids；主 status 是提交接口的既有权威状态。权限由 users 和有效岗位/角色菜单解析；未修改账号权限和真实费用。

## 修改清单及入口矩阵
- 单条打印、合并打印、查看后切打印：按主状态判断已审批/待付款；接口返回当前身份提交/核销能力，前端据此显示按钮。
- 单条和批量提交：统一校验有效待付款菜单权限并保留可见记录范围、状态、收款对象、银行账号及合同专用动作约束。
- 待核销：使用对应核销菜单能力，不混用提交权限；终态不出现提交按钮。
- 无授权身份：前端不显示办理按钮，后端拒绝。提交失败显示真实错误，成功进入待核销。
