## 用户原文（保持不变）

本次会议主要围绕律所管理系统的功能测试与逻辑对齐展开，重点讨论了合同、案件、调查任务及财务中心之间的业务流转关系，明确了当前系统在合同付款/开票界面、提成计算绑定及部分冗余字段显示上存在的问题，并制定了本周优先打通财务流程及调整会议沟通频率的计划。

## 1. 合同与案件基础逻辑

- **合同台账概念**：合同实质为合同台账，基于客户建立，一个客户可关联多个合同，合同号按年份生成；案件必须依附于合同存在，支持一个合同对应多个案件或一个案件对应多个合同的多对多关系。
- **新建流程验证**：确认了从客户管理或合同中心均可新建合同，且能正常关联客户；在合同下新建案件及调查任务的功能基本走通，调查任务可进一步分解为子任务并生成线索。

## 2. 调查任务与线索流转

- **角色权限分配**：明确了不同角色在调查大厅的视图差异，案源人负责发布任务和审核线索，调查主管负责分配子任务，调查员负责执行任务并上传线索；目前仅实现了菜单级权限，操作级权限待后续细化。
- **线索与任务关联**：澄清了线索归属于具体调查任务之下，同一任务可产生多条线索；线索经审核后进入取证环节，最终生成案件，该链路目前已测试通过。

## 3. 费用管理与财务流程

- **费用分类逻辑**：系统费用分为合同相关费用（官费、代理费，涉及对外结算）和内部费用（提成、扣款，涉及内部分配）；律师在案件中录入费用后，需通过“申请付款”动作提交至财务中心，否则财务端不可见。
- **付款与开票缺陷**：当前合同模块中的“申请付款”和“申请开票”界面存在缺陷，未正确绑定案件费用且弹窗简陋，导致流程卡滞；需参照老系统逻辑修复界面，确保数据能流转至财务中心的请款单审批及待付款列表。
- **回款与结算管理**：财务中心支持银行流水导入以匹配回款，律师需协助确认款项归属；结算管理涉及律师与律所的对账，包含归档费结算逻辑（未归档扣留5%），平台财务中心则处理司法汇城平台的合同收支。

## 4. 系统问题与优化计划

- **冗余字段清理**：发现系统中存在源自旧代码的冗余功能，如“资助费用”、“案件提醒”、“案件事件”及“VIP筛选”，这些在现行诉讼系统逻辑中无需体现，需进行屏蔽或删除。
- **提成计算绑定**：新增代理费后无法自动计算并显示人员提成，原因是人员与提成比例未正确绑定；需检查经办律师等角色配置，确保修改人员信息后能触发正确的提成计算逻辑。
