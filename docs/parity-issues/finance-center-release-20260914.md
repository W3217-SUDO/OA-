# 财务中心 11 项逻辑整改统一发布记录

## 范围

本批次来自旧系统说明书、旧系统源码和隔离复现结果，按用户指令“全部问题都要改完啊”统一实施和发布。每项独立定位记录见 `finance-center-fc01-remediation.md` 至 `finance-center-fc11-remediation.md`。

| 编号 | 修复结果 | 自动化验收 |
|---|---|---|
| FC-01 | 结算额与归档费改由后端按费用和归档状态计算 | 客户端伪造金额被忽略；代理费、归档费准确到分 |
| FC-02 | 其他费用不再进入一般结算应付额 | 其他费用结算贡献为零 |
| FC-03 | 未完整分配到账不能提交结算 | 部分分配返回 409 且不生成申请 |
| FC-04 | 缺少旧明细时按分配记录中的精确费用 ID 回溯 | 多费用环境仍定位原费用 |
| FC-05 | 删除到账对费用、应收计划和流水做对称回滚 | 删除后费用实收与来源字段恢复 |
| FC-06 | 批量撤销分配复用同一回滚逻辑 | 撤销后费用与到账分配一致恢复 |
| FC-07 | 有效结算关联的到账禁止删除或撤销 | 已付款结算关联时返回 409 |
| FC-08 | 重提刷新财务快照；提交、重提和审批增加重复及陈旧保护 | 重提刷新、重复申请阻断、陈旧审批阻断 |
| FC-09 | 同客户费用可跨案件、跨合同合票，并保留各来源明细 | 双案件、双合同合票成功 |
| FC-10 | 恢复高开并记录超额金额 | 费用 100 开票 120，记录超额 20 |
| FC-11 | 按金额累计发票占用，部分开票后保留剩余额度 | 先开 40 后仍可开 60，余额归零后移出候选 |

## 验证

- 后端：18 项针对性回归通过。
- 后端静态检查：财务核心、路由和请求模型编译通过。
- 前端：多费用发票载荷断言通过；TypeScript 与 Vite 生产构建通过。
- 数据：测试使用内存 SQLite；没有读取或写入业务数据库。
- 发布数据范围：应用代码和前端静态资源；不含数据库结构或数据变更，因此无需数据库备份。

## 规则边界

旧材料能确认代理费结算、归档留存和高开的业务链，但没有确认“未归档扣留 5%”的金额基数。本批次保留当前服务端 80% 结算额、按结算额 10% 留存的公式，并消除客户端绕过、金额错算和生命周期不一致。若业务另行确认 5% 的具体基数，再按该规则单独调整公式。
