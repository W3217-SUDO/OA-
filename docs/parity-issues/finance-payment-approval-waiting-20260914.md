# 费用审批后进入待付款列表整改记录

## 原始问题与截图

用户原话：`这笔费用审批完应该自动跳转到代付款列表啊 为什么审批完就没有了啊`。截图显示请款单审批列表中的官方费用和代理费记录；“代付款”按页面实际名称统一理解为“待付款”。

VibeHub 以脱敏短词“状态流转”“待付款队列”核对，无可靠词条匹配，未采用不相关链接。

## 旧系统证据

- 旧系统 `PaymentObjectStatus` 明确定义 `P=待审批`、`Approved=待付款`。
- 旧系统 `PaymentService.Audit` 在最终审批通过时把付款对象状态写为 `2`，即 `Approved/待付款`。
- 因此审批通过后的费用应退出待审批列表并进入待付款列表。

## 新系统根因

- 审批接口只把 `BusinessRecord.status` 从 `待审批` 改为 `已审批`。
- 同一费用的 `data.payment_status` 仍为 `待审批`。
- 待付款查询和页面展示优先使用 `data.payment_status`，导致记录从待审批移除后又被待付款条件排除。

## 修改

- 审批通过时同时写入 `payment_status=待付款`，驳回时写入 `payment_status=已驳回`；单条、批量和审核抽屉入口共用同一状态函数。
- 费用查询以主状态投影付款状态，使已经受影响、仍保存旧 `payment_status` 的记录无需数据迁移即可重新出现在待付款列表。
- 前端使用同一主状态优先规则，避免缓存或通用记录接口返回旧扩展字段时再次隐藏。
- 登记付款及删除付款流水时同步付款状态，保持待付款、部分付款、已付款之间一致。

## 验证与发布

- 后端动态测试覆盖通过、驳回和既有陈旧记录投影。
- 前端测试覆盖陈旧状态、部分付款、已付款和不缴费例外。
- 无数据库结构或数据修改；既有记录通过读取投影恢复，无需批量改库。
- 正式部署后状态为待用户在 8089 验收。
