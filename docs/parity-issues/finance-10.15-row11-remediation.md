## 新系统链路

- 合同请款编辑页面：`apps/admin-web/src/finance/ContractPaymentEditPage.tsx`，通过 `GET /contract-payment-applications/{id}/edit-context` 加载，保存使用 `PUT /contract-payment-applications/{id}`，勾选“保存并重新提交”后再调用 `/submit`。
- 页面当前提供“保存修改”和“保存并重新提交”按钮，并以 `canEditContractPayment` 和状态判断编辑资格；需要验证回滚后的实际状态是否进入该条件。
- 后端编辑入口：`apps/api-server/app/areas/contract/router.py:1451-1470`，调用 `ensure_editable/ensure_unsettled`；需核对到账分配、已付款、已核销和回滚状态的阻断。
- 普通财务费用另有 `FinanceFeeModals.tsx` 的“保存修改”路径；本行必须按真实测试数据确认普通费用和合同请款两种来源的行为，不得只测合同页面。

## 原子验收项

1. 回滚后的专属 CODEX 请款记录出现在“我的请款单”，状态与金额正确。
2. 申请人进入编辑页面，原字段、费用明细和关联案号完整回显。
3. 存在到账分配时保存被明确阻断，提示与旧系统业务含义一致。
4. 撤销到账分配后，保存修改真实落库；“保存并重新提交”真实改变状态并回到审批链。
5. 失败路径、权限和两种付款来源均有接口/数据库回读，测试记录和分配记录全部清理。

## 定位结论

本行要求的是完整的“回滚 -> 我的请款单 -> 编辑 -> 保存 -> 再次提交”状态链，而不是单独显示编辑按钮。集中实施时必须使用唯一 CODEX 请款数据验证状态、分配阻断、持久化和再次提交。
