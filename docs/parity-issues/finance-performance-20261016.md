- 本地数据库与服务器数据库结构一致，核心财务数据已核对：回款 3203 条、旧财务记录 85843 条、用户 168 条、附件 161869 条。

## 旧系统对照

旧系统 `/5001007001/FAM/Settlement/PendingList` 使用服务端筛选、汇总和分页，回款主表与回款对象表按 `PaymentId` 关联；当前页才返回明细。旧系统的结算金额、归档金额和状态由服务端重新计算。

## 本次修改

1. 回款查询分成轻量汇总扫描和当前页明细批量读取，保留筛选、排序、汇总和返回字段。
2. 结算候选只读取当前回款关联的 `finance_settlement` 记录，不扫描整表。
3. 付款工作流把逐条读取付款包改为按付款包 ID 批量读取，并保留无权访问时的 404 行为。
4. 发票和内部费用查询将主表可直接判断的条件下推到数据库；案件关联、申请人显示名、日期解析和生命周期等派生条件仍按旧逻辑在应用层复核。
5. 通用结算查询仅下推回款主表的付款人和日期条件；客户条件仍保留应用层判断，兼容客户来自案件明细的旧数据口径。结算回款关联使用 JSON 文本比较，兼容历史数字和字符串 `receipt_id`。
6. 历史结算投影增加可见历史回款头为空时的轻量短路；存在历史源时继续使用原投影和状态校验，保持旧系统口径。
7. 新增版本化启动迁移 `legacy_settlement_query_indexes_v1`，补齐历史回款头和明细父子联接复合索引；本地启动后已确认迁移键和索引存在。
8. 归档投影改为一次读取基础行后计算未知状态、金额汇总和分页，避免重复执行同一统计 CTE；同时从可见回款头集合起步联接历史明细。SQLite 归档/导出回归恢复为 `48 passed, 7 skipped`。
