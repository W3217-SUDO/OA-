# 案件关联详情审计源码覆盖误报

- **发现日期**：2026-09-12
- **问题类型**：审计工具缺陷
- **前端位置**：案件中心列表/关联入口；`queriesActions.tsx` 的案件详情目标消费与 `workflowActions.tsx` 的 `openCounselDetail`
- **旧系统对比**：关联案号必须先解析可见的核心案件记录，再进入案件详情并加载附属面板。
- **新系统现状**：当前实现已通过 `consumeCaseDetailTarget()` 按 ID/案号解析核心记录，随后调用 `openCounselDetail(linkedCase)`。
- **误报根因**：审计脚本仍要求旧版本集中在单个函数中的 `recordRes -> setViewingCounselCase` 字符串，无法识别当前拆分后的调用链。
- **整改**：审计改为检查目标消费和受控详情入口两个真实契约。
- **状态**：已修复审计误报，待完整审计继续验证。
- **验收映射**：案件中心列表案号/关联案号；目标记录 ID、案号；案件详情入口。
