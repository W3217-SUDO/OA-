# 员工资料保存被未变更部门阻断

## 问题状态

- 页面位置：人事中心 -> 员工管理 -> 修改 -> 员工完整资料修改 -> 提成设定 / 保存全部修改
- 用户现象：只修改人员提成数据，未修改部门，保存时提示“所选部门不存在或已停用”。
- 截图证据：`codex-clipboard-d4bed71e-2d5b-4e6e-89dc-1b8211d424ec.png`
- 当前状态：代码整改完成，待发布

## 需求确认

- 未修改部门时，员工资料保存不得被部门主数据现状阻断。
- 未修改部门时，不得借由本次保存隐式覆盖员工档案或登录账号已有的部门值。
- 只有用户实际选择了不同部门时，才校验目标部门存在且启用，并同步更新员工档案与登录账号。

## 定位结论

- 前端员工资料弹窗提交完整表单，因此即使只维护“提成设定”，当前部门也会随请求再次提交。
- 后端 `update_hr_employee` 对每次请求都执行启用部门查询，没有区分部门字段是否发生业务变更。
- 后端随后无条件把请求中的部门同时写入员工档案和登录账号，存在无关编辑触发部门同步的副作用。
- VibeHub 术语检查：已调用；候选“partial update / dirty fields”未返回适合本问题的精确术语，无需补充术语链接。

## 整改方案

- 以编辑页面实际展示的当前部门为基准判断部门是否发生变化。
- 部门未变：跳过启用部门校验，并分别保留员工档案、登录账号原部门。
- 部门有变：校验新部门存在且启用，再同步写入员工档案与登录账号。
- 保持新建员工和其他人事权限、角色、职务校验不变。
