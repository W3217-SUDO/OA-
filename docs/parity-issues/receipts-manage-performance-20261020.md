# 回款管理接口提速（1.1.485）

- 日期：2026-10-20
- 接口：`GET /api/v1/finance/incoming-payments?view=finance-receipts-manage`（财务中心 / 平台财务中心 → 回款管理）

## 根因

1. 页面每次都提交 `filters={}`，后端把“带了 filters 参数”当成有筛选，从不走只读汇总表的快速分页路径，每次现算全部回款的历史分配金额。
2. 回款与历史表头的关联条件是 OR（按 ID 或按回款编号），PostgreSQL 只能嵌套循环，约 2,000 万次比较。
3. 生产的只读汇总表 `hz_incoming_allocation_read_models` 为空（0 行），快速路径即使启用也会退回慢路径。

## 修改（提交 `87a5352d`，版本 1.1.485 `6b6525fd`）

- `has_effective_incoming_filters`：与 `matches_incoming_filters` 相同的跳过规则；无实际筛选时走快速路径。
- 快速路径合计输出全部 `TOTAL_FIELDS` 键（补齐“金额”“到账金额”）；当前页按慢路径同一口径读取（只聚合本页表头），行字段由同一函数计算。
- `_incoming_source_relation` 改为等价的单一组合键等值关联，可走哈希/归并连接。

## 生产数据回填（用户确认，2026-10-20）

- 只读预演：3,202 条 HZ 回款全部通过校验，0 条拒绝。
- 执行 `backfill_hz_allocation_read_model`：写入 3,202 行（3,186 条重算一致，16 条采用已核验旧基线）。
- `incoming_payments` 全表指纹回填前后一致（`3a56ef03…`，3,203 行），回款数据未改动。
- 回滚：`DELETE FROM hz_incoming_allocation_read_models;`（回填前为空表）。

## 验证

- 本地：新旧代码 172 个返回结果对比，除无 filters 参数请求补齐两个合计别名外逐字节一致；结算申请、待归档、归档付款、财务概览等经同一关联的接口 108 个结果全部一致。
- 生产：快速路径与原慢路径对比 12 组（admin / 普通财务账号 × 律所 / 平台 × 3 种分页）全部一致。
