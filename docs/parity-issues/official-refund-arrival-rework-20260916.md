# 官费到账后退费显示返工

## 1. 原文
官费这里显示50未退，但是这笔费用已经全部回款了，说明这50已经到账了，这时这里要变成50（已退），比如说如果这里回款了30，那就是显示20（未退）了

本次为用户再次明确的直接问题。此前“法院退费到账”补充保留。本轮以用户明确的同一费用到账规则修正上轮仅识别退款标记的限制。状态：线上未通过/返工。

## 2. 唯一截图

## 3. 旧证据与本次规则
此前逐图记录与旧 PaymentService.cs 已确认 IsRefund 单独增加退款账务字段。该账务分类继续保留，但不能用此限制替代用户明确要求的到账进度显示。本轮只改变同一官费的进度计算，不把历史普通回款流水改写为法院退款。

## 4. 新系统根因与数据证据
legal/router.py related_dict 汇总关联退款单，把 refunded_amount 覆盖成状态为已退款的退款单金额；已聚合的 incoming_by_fee.received_amount 未参与。因此回款100仍显示50未退。

线上只读查明：目标官费已有 received_amount=100；incoming_payments.allocations 通过 fee_record_id 和 settlement_items 指向该费用，属于真实已分配回款。申请50由关联 refund 记录在读取时投影，不能只查费用JSON就断言没有应退金额。上轮遗漏了关联退款单投影及用户明确的到账显示规则。

实体：business_records(finance/refund)，incoming_payments.allocations；关联 fee_record_id。撤销分配会删除关联分配并扣回 received_amount。无数据库迁移或历史数据改写。

## 5. 修改与入口矩阵
- 共用官费退费进度函数：有效已退=min(应退, max(已有已退, 本费用到账))，不把两者相加；不足显示差额，足额显示应退总额已退。
- 案件律所/平台费用读取：关联退款单应退金额与同费用分配金额共同投影。
- 财务费用查询/退费查询：使用同一进度，含旧费用字段回退，保持金额权限隐藏。
- 法院退费候选和提交限额：扣除已经到账的进度，避免显示已退后仍重复分配。
- 案件未退汇总：采用同一应退差额。代理费、内部费用不采用官费规则；不再办理状态继续保留。
- 撤销分配：沿用真实分配删除和 received_amount 扣减，下一次读取重新计算，不写死已退状态。
