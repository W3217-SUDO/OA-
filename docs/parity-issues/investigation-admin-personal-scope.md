# 调查中心管理员个人路由数据范围错误

## 当前结论（2026-09-12 源码复核后，覆盖下面的初步判断）
- 已撤回本轮给个人线索 `-my-` 过滤新增的 `!isActualAdmin` 条件，保持原来的 owner 二次隔离。
- `areas/legal/router.py:641` 明确对所有角色的个人线索列表执行 `scope=mine`；不能把个人调查任务的管理员判断泛化到线索队列。
- 旧 `InvestigationClueController.List` 依赖业务服务筛选，当前只读 Web 源码不足以推出个人线索管理员例外，旧源码证据见 [legacy-area-baseline.md](./legacy-area-baseline.md)。
- 两个历史线索测试改读真实模块：创建/导入 publisher 追踪仍需验证，但它不是当前负责人归属；补强个人过滤中不含管理员绕过的断言。
- 本轮状态：初步整改撤回，不再计作真实缺口修复；原有普通调查任务真实管理员判断未修改。
- 五个定向测试文件 14/14 通过，仍不是浏览器、真实角色或数据库验收。未部署。

## 早期记录（保留追踪，以下推断已被上文纠正）

- **发现日期**：2026-09-12
- **问题类型**：权限与数据范围未对齐
- **前端位置**：调查大厅 -> 我的调查任务/我的调查线索；调查中心 `InvestigationCenterPage`；个人路由 `*-my-*`
- **旧系统对比**：管理员具备全所调查数据权限；“我的”入口的个人语义不能覆盖管理员的全所可见范围。
- **新系统根因**：`visibleRows` 的 `initialTab.includes("-my-")` 过滤未排除管理员，在接口返回管理员可见数据后又按当前用户名二次过滤。
- **整改**：改为仅在 `!isActualAdmin` 时执行个人过滤；管理员保留接口返回的全所范围。同步更新结构审计断言，检查三类个人路由。
- **状态**：已修复，待本地构建与定向验证。
- **验收映射**：菜单“调查大厅”；页面标题“调查任务列表/调查线索列表”；个人路由筛选与表格数据范围。
- **残余风险**：尚未执行真实管理员账号浏览器验收；需验证普通成员仍保持个人范围、管理员仍能看到全所记录。
