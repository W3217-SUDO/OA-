# 我的共享客户：操作按钮范围对齐疑点

- 状态：已核实旧模板差异，按用户后续菜单授权要求保留新系统操作，不作删按钮整改
- 前端页面：客户管理 -> 我的共享客户
- 路由：`customer-shared`
- 前端位置：`apps/admin-web/src/crm/CustomerCenterPage.tsx` 的 `originalActionItems`
- 相关按钮：客户编辑、客户删除、分配客户、释放到公海、新增合同、新增沟通记录、联系人管理、共享客户、客户服务端操作

## 当前定位

当前实现将 `customer-shared` 与我的客户、部门客户、公司客户等列表共同归入 `completeCustomerActions`，因此共享客户页面会得到完整操作集。

## 对齐要求

旧源码 `Areas/CRM/Views/Customer/CustomerList.cshtml:321-326` 的 6001007 底部菜单分支为空，423-426 右键分支仅“客户查看”。6001008/6001009 的最近联系/更新为查看和编辑；部门/公司为查看和分配。此为实际模板证据，不是先前按菜单名作出的猜测。

用户后续明确要求：“所有的页面都是的，只要客户可以看到这个菜单，所有的权限就要开放”。因此新系统增加动作属于用户要求的差异，不能以旧模板没有为由移除。仍须逐动作检验数据范围、状态及持久化，不把菜单授权解释为删除业务阻断。

## 处理状态

本轮不修改 `originalActionItems`，保留其完整操作集，不声称所有按钮已验收。实际发现共享弹窗移除人员不生效，单独记录并整改于 [customer-share-removal.md](./customer-share-removal.md)。
