# 财务中心 / 平台财务中心 查询接口提速（1.1.491）

- 日期：2026-10-20
- 版本：1.1.491（`6461485a`），基于 1.1.490
- 范围：两个菜单下的回款、请款付款、内部提成、开票、结算、归档费结算、费用查询、导入数据核对页面使用的查询与导出接口

## 根因与修改

| 根因 | 影响接口 | 修改 |
|---|---|---|
| 读取一笔或少数几笔回款时，旧系统分配金额仍按**全部**可见回款头聚合；发票导出按每 400 个回款分批，每批都全量聚合一次（生产 7 次） | 单笔回款详情、查看分配、分配/退款候选、分配记录、认领/分配锁定、合同回款、发票导出、结算导出、交接投影 | `incoming_source_for` / `payment_conditions`：只聚合实际读取行的回款头 |
| 每行明细的“费用类别”表达式被内联进每个聚合列，按列重复计算并重复解析原文 JSON | 所有依赖旧分配金额的回款、结算列表 | 逐行证据物化一次（MATERIALIZED CTE） |
| 迁移费用字典关联被估为 1 行而走嵌套循环，每行明细按主键查找全部字典（数十万次） | 结算投影、旧分配金额 | 唯一字典行先物化（64 行） |
| 结算投影从案件取 9 个字段，文本 JSON 每取一次就解析一次 | 待归档 / 归档付款 / 已付 / 已拒绝及导出、一般结算申请 | 按主键关联后 LATERAL 转 jsonb 一次（`OFFSET 0`） |
| 财务概览逐行从完整费用 JSON 取 `amount`、`fee_type` | 财务概览 | 改读触发器维护的精简读模型（原值复制），缺行回退原表 |
| 已验证但此前未上线的两项 | 票据文件、案件费用退费 | 只读必要列、批量放大；退费复用已读费用、人员显示名只补当前页 |

## 验证

- 本地生产数据副本，新旧代码对比 288 个返回结果（管理员与普通财务账号 × 律所 / 平台，列表、详情、候选、导出文件哈希），全部逐字节一致；两边各 122 个业务报错内容一致。财务概览另行比对 4 个结果一致。
- `jsonb` 转换前核对：生产 6,461 条案件全部可转换（无 `\u0000`）。
- 定向测试 119 项通过；推送 `dev` 的源码门禁通过。

## 仍偏慢（未处理）

| 接口 | 生产耗时 | 原因 |
|---|---|---|
| 费用查询 / 导出 | 6～16 秒 | 8 万条费用在 Python 中逐行计算发票、付款、到账、退费关联并筛选；需把筛选下推到 SQL |
| 内部费用列表 / 导出 | 3.2～8.9 秒 | 同上（共用费用行引擎） |
| 案件费用退费 | 约 8 秒 | 同上 |
| 待打包候选 | 4 秒 | 同上 |
| 发票导出 | 约 21 秒 | 剩余为逐张发票的费用明细投影 |
| 待结算 | 2～5.5 秒 | 待分析 |

已知限制：今后若有案件数据含 `\u0000` 字符，jsonb 转换会使结算投影查询报错，需改回原写法或清洗该条数据。
