# 催收代理费任务完成条件不一致

2026-09-13；状态：已本地修复，隔离回归通过；未浏览器验收、未部署。

- 前端：案件详情 -> 案件任务 -> 催收代理费 -> 状态；CaseTasksPanel.tsx，后台扫描结果经 GET /cases/{id}/tasks 显示。
- 旧证据：legacy-auto-task-rules-20260913.md 所列 TaskDao.cs:1323；指定四类代理费不存在 Amount-ISNULL(CashedAmount,0)>0 的记录，才筛为完成候选。
- 新证据：apps/api-server/app/core/tasks.py:1217、1307、1347；先收集 received_date<=今天-30天的 IncomingPayment，再以案件存在任意关联到账记录作为催收任务完成条件，没有核对代理费类别及是否全部收齐。
- 影响：存在30日前到账但代理费仍未收齐的案件可能提前结束催收；刚刚收齐的款项又不在这批30日前到账集合中。不能把存在到账记录等同于指定代理费结清。
- 整改：`app/core/tasks.py` 将催收完成与到账30日归档拆开；仅核对同案件有效的11020010/20/30/40费用，费用投影与明确费用分配关联的到账分别计算，不重复相加。当前案件ID冲突时不接受旧ID兜底，也不按客户名称猜归属。
- 数据不完整保护：没有有效费用证据或金额不可解析时不自动完成；旧CashedAmount为空按0处理，非有限金额不能作为结清证据。无费用记录暂缓完成是迁移证据不足的保护，不宣称与旧NOT EXISTS零行语义完全等价。
- 验证：`automatic_task_legacy_agency_fee_rules_test.py` 8/8，涵盖部分到账、其他款项、当日到账、无费用、冲突归属、多任务单次收款查询及跨会话落库；内存SQLite随引擎关闭清理，未触碰业务数据。
