## 对会议的理解

主线是以客户和合同台账承接业务，以案件及调查记录承接执行，以逐笔案件费用承接财务，而不是单独完善几个弹窗。

1. 客户 -> 合同；按用户后续澄清，案件头部只显示建案时的合同。新建每笔案件费用可选择其他合同，该笔费用归集到所选合同，不反向替换案件头部合同。不得将多对多理解成案件头部必须显示多个合同。合同也可发起调查 -> 子任务 -> 线索 -> 审核/取证 -> 案件。
2. 案件费用录入与付款申请必须分开。付款链为费用 -> 请款 -> 审批 -> 待付款 -> 实际付款/核销。
3. 开票是独立链：关联可开票费用 -> 发票申请 -> 审批 -> 待开票。不能把开票当成付款，也不能要求发票进入待付款列表。
4. 回款是另一条链：银行流水 -> 认领客户/确认归属 -> 分配案件费用 -> 更新回款和结算。
5. 内部提成依赖案件人员及比例规则；归档留存是结算规则，不等同于开票金额或外部付款。
6. 本次会议要求裁剪的诉讼界面内容，应按当前业务决定隐藏，不因为旧代码存在就强行保留；历史数据不随界面裁剪删除。
