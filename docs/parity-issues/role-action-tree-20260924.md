# 9.22 在线表格第 22 行：角色案件动作权限树

- 用户入口：人事中心 -> 角色管理 -> 角色列表 -> 权限设定 -> 菜单及动作权限。
- 用户期望：案件操作显示在所属菜单的下一层，逐项勾选后对相应角色生效；不是仅在案件页隐藏按钮。
- 原问题：角色接口把历史动作集中放在树末尾，案件动作目录未挂入菜单；旧“案件承办”标签还会一次授予多个动作，单纯增加复选框不能实现逐项撤销。
- 整改：角色权限树按动作目录的 `menu_key` 将动作挂到实际菜单下；前端菜单复选框与动作复选框独立，菜单勾选仍联动其子菜单；保存时把旧案件标签转换为对应菜单和明确的动作键，并标记该角色已采用逐项案件动作配置。未保存的旧角色权限不变。
- 涉及源码：`apps/admin-web/src/OrganizationCenterPage.tsx`；`apps/api-server/app/areas/hr/router.py`；`apps/api-server/app/core/permissions.py`；`apps/api-server/app/core/constants.py`；`apps/api-server/app/models_shared.py`。
- 验证：三项角色树/角色权限回读定向检查通过，原岗位权限策略三项检查通过；前端生产构建和 Python 编译通过。菜单覆盖审计因当前基线预期 288、实际 289 个旧菜单节点而失败，非本次变更造成。
- 数据：当前线上只读确认“合伙人律师”“主办律师”仍使用“案件承办”历史授权；本次发布不修改角色记录，管理员保存某角色权限时才更新该角色 JSON 权限列表，无数据库结构迁移。
- 状态：本地改动完成；发布和用户页面验收结果待补。用户验收前不得写为 `1`。
