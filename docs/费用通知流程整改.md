# 费用通知流程整改

【任务】费用通知流程（新建费用信息/到账确认/上传票据）

【背景】
旧系统有独立的"费用通知→到账确认→上传票据"流程（右键菜单含新建费用信息、到账确认、上传票据、查看票据文件、解锁、删除、关联费用信息）。

【前端代码位置】

- 搜索"通知"或 inform 或 票据 找到相关代码
- 查看费用Tab的操作菜单

【后端代码位置】

- 搜索 fee inform 或 费用通知 或 到账确认 或 票据 相关接口
- 确认现有费用模块的数据结构
- 参考其他费用操作的实现

【修复要求】
1. 在案件费用列表增加费用通知相关操作
2. 功能包括：
   - 新建费用通知/费用信息
   - 到账确认
   - 上传票据文件
   - 查看票据文件
   - 费用通知解锁

3. 后端：

4. 保持与现有费用操作风格一致
5. 完成后本地构建验证无编译错误

## 证据与旧系统还原

- 旧系统只读源：`GD.CRM.WEB.VIP/Areas/IPR/Lawsuit/Views/Case/PartialView/CaseFeeList.cshtml`。费用右键菜单包含新建费用信息、到账确认、上传票据、查看票据文件、解锁、删除、关联费用信息和刷新。
- 菜单权限：`CreateCaseFeeInform` 控制新建；`ConfirmCaseFeeInform` 控制到账确认；`ConfirmCaseFeeBill` 控制上传票据；`UnlockCaseFeeFile` 控制解锁；`DeleteCaseFeeFile` 控制删除。查看票据与关联费用信息在页面模板中未设独立显示权限。
- 旧控制器：`Areas/IPR/Lawsuit/Controllers/CaseFeeController.cs` 的 `CaseFeeInformCreate`、`CaseFeeConfirmCreate`、`CaseFeeBillConfirmCreate`、`CaseFeeUnlock`、`CaseFeeDelete`、`CaseFeeLinked`。
- 创建通知：通知日期默认当前时间；要求费用类型、收费人；年费的年限必须为正整数；可包含多条费用明细、减免标记和应收金额。
- 到账确认：默认到账日为当天、实收金额为应收金额；旧页面校验应收金额、实收金额和到账日期必填，且强制应收与实收相等。
- 上传票据：票据编号、票据金额、票据日期、票据文件均为必填；保存时持久化文件名、文件大小和文件内容，查看票据走受控下载入口。
- 关联费用信息：选中的费用明细 ID 作为列表提交；解锁和删除针对费用记录 ID。
- 旧页面在有费用明细行时才将该行的 `FeeItemId` 交给到账确认、上传票据和查看票据；解锁和删除使用父费用 `FeeId`。关联操作至少要求选择两项。这说明通知明细与费用通知父记录不是同一对象，不能将“关联”实现成同一行自引用。

## 新系统现状与差异

- `CaseCenterPage.tsx` 的案件费用页已具备一般费用的新建、付款、开票、修改、删除和标记不缴费菜单，但缺少独立费用通知、到账确认、票据上传/查看、解锁和关联费用操作。
- `main.py` 已有知识产权案件费用的查询、创建、开票、付款、到账、解锁、删除接口（`/ipr/cases/{case_id}/fees/...`），但没有可替代旧票据确认的票据附件上传/下载接口，也没有费用通知多明细/关联费用信息的专门业务接口。
- 现有到账接口使用收款流水模型，不等同于旧流程中单笔费用确认的“应收=实收”门禁；实现时需要明确费用通知状态与到账确认状态，不能仅复用前端提示。
- `BusinessRecord(module="finance")` 的 `data` 已是费用扩展字段承载体；新增字段应与现有 `amount`、`cashed_date`、`cashed_amount`、`locked`、`is_locked` 一致保存，并通过真实附件记录保存票据，而非仅保存文件名。
- 旧通知对应费用父记录和费用明细的两层关系；新实现若以独立 `finance` 记录承载通知，必须为其保存目标原费用 ID 列表，关联时拒绝本身、重复 ID、跨案件 ID、已删除/无权限 ID，并确保不会再次把同一费用金额写入应收或到账汇总。

## 整改范围

1. 前端费用 Tab：仅在相应能力和选中记录条件满足时显示菜单；新建通知可保存通知日期和通知费用明细；到账确认、票据上传、查看、解锁和关联均调用真实接口并刷新列表。
2. 后端：为费用通知设计输入模型和专用接口；逐项校验案件归属、记录可见范围、案件可写状态、操作能力、状态前置条件与关联记录归属。关联目标至少两条，不能自关联或跨案件，且操作幂等并防止重复计费。
3. 票据：使用现有附件存储与下载授权链路。上传要校验非空文件，成功后将附件 ID、名称及票据字段写回费用记录；上传必须以已到账、未删除、未锁定等明确业务前置为条件。下载必须从费用记录反查附件 ID，校验费用与案件归属及当前用户可见性，不能接受任意附件 ID。
4. 审计：每个创建、到账确认、上传票据、解锁、关联及删除动作写入案件和/或费用工作流事件；失败不留下半成品。
5. 验证：覆盖无权限、非本案费用、不可写案件、重复到账、未到账上传票据、无附件查看、关联跨案费用等阻断；运行前端生产构建和 Python 编译。

## 验收清单

- 新建通知后列表回显通知日期、应收金额、通知状态及关联明细。
- 到账确认后回显到账日期、实收金额和确认状态；不满足应收=实收、未通知、已确认或删除/锁定等状态规则时返回明确错误。
- 上传票据后回显票据编号、金额、日期和可下载文件；仅已到账且未锁定的通知可上传。无附件时查看操作给出明确提示。
- 关联至少两条同案原费用，拒绝自关联、跨案件、重复关联及会产生重复计费的关联；列表总额不因关联重复累计。
- 解锁、删除和关联均验证权限、案件归属和状态，且刷新后状态与审计记录一致。
- 当前任务没有 Excel 行或截图附件；VibeHub 由主会话已核对“状态机”，未返回可用候选，不额外添加术语。

## 实施与验证状态

- 实现：费用通知作为独立 `finance_fee_inform` 记录落地；到账确认创建受控 `IncomingPayment`、回写来源费用的到账字段；票据附件绑到通知记录并经通知入口下载授权。关联拒绝来源费用自身、跨案件、重复选择和被其他通知占用的费用。
