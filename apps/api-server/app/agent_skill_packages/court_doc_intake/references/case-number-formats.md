# 官方案号形态与脏数据处理

## 一、OA 系统官方案号字段概况

| 字段 | 内容 | 填写率（403 件样本） |
|---|---|---|
| `data.court_case_no` | 法院/检察/仲裁/调解官方案号 | **47.6%**（192/403） |
| `data.court` | 法院代字（如"皖0402""浙8601"） | 71.5%（288/403） |

**关键**：超过一半案件未登记官方案号，必须走当事人反查。

## 三、脏数据类型与清洗（实测 192 条有值记录）

| 脏数据形态 | 数量 | 实例 | 清洗方法 |
|---|---|---|---|
| **括号内插入空格** | 17 条 | `（2025）渝 0 103民 初 40009 号`<br>`（2026）赣 0203知民初32号` | 去所有空白字符 |
| **括号不配对**（全/半角混用） | 10 条 | `（2026)苏12民初46号`<br>`(2025苏0214民初15189号`<br>`(2026）浙0784民初3140号` | 半角`(`→`（`，`)`→`）`；年份后补右括号 |
| **一个字段塞多案号** | 5 条 | `（2026）苏0581民初7641号（ 2026）苏0581民初18335号`<br>`（2026）皖1323民初3251号 （2026）浙8601民初764号` | 按「（YYYY）」边界拆分，多为关联案/一审二审 |
| **缺「号」字** | 9 条 | `（2026）粤0604民初 816` | 补「号」 |
| **纯数字编号** | 1 条 | `121925000768` | 直接用keyword 整体匹配 |

**脏数据率约 17%**（33/192）。直接拿文书原文检索这些案号会匹配失败。

## 四、归一化工具

用 `harness_run_skill_script` 执行，path=`scripts/normalize_case_no.py`，args=`["<案号>"]`。
OA 工具“下载法院送达文书”返回的每份文书已自带归一化案号和检索变体，通常不必再单独运行。

**输出字段**：`归一化`、`年份`、`受理机关代字`、`类型`、`序号`、`检索变体[]`

**检索变体**（按精确→宽松排列，逐一尝试）：
1. `（2026）皖0402民初4093号` —— 完整格式
2. `2026皖0402民初4093号` —— 去括号
3. `皖0402民初4093号` —— 代字+类型+序号
4. `皖04024093` —— 代字+序号
5. `4093` —— 纯序号（最宽松，噪声大）

**输入含多个案号时自动拆分并 stderr 警告** —— 说明可能是关联案/一审二审，须分别检索确认，不能只查一个就认定匹配。

## 五、匹配噪声实测

同一案件（已登记 `（2026）皖0802民初2990号`）用不同变体检索：

| 检索词 | 命中数 | 评价 |
|---|---|---|
| `（2026）皖0802民初2990号` | **1** | ✅ 干净，唯一命中 |
| `皖0802民初2990` | 1 | ✅同样干净 |
| `皖0802` | 9 | ❌ 噪声大（同一法院其他案件） |
| `2990` | 3 | ❌ 噪声大（序号可能撞号） |

**结论**：优先用完整案号。宽匹配（仅代字、仅序号）几乎必然误匹配，命中多个时必须列候选让用户选，绝不自行判断。

## 六、系统中`court` 字段的坑

`court` 字段存**法院代字**（如 `皖0402`、`浙8601`、`沪12`），**不是法院全称**。

- 用"淮南市大通区人民法院"查 → 0 条
- 用"大通"查 → 0 条
- 用"皖0402"查 → 5 条（含本案的法院代字）

另注意：`court` 字段也存在脏数据，如 `GDMS2300580` 的案号是「（2024）浙0192民初4068号」但 `court` 字段却是`湘0521`——**两者可能不一致，不可完全信赖 `court`**，只作为缩小范围的辅助维度。
