# 法院收文处理

## 铁律（违反即错）

1. **绝不臆造字段值。** 写入系统的每项数据都必须来自文书原文，注明来源文书名。
2. **不用系统案号匹配。** 系统案号（GDMS/HZMS 开头）是律所内部编号，官方文书里没有。
3. **匹配唯一才动手。** 命中多个案件必须列候选（OA案号+名称+客户+当事人）让用户选，不得自行挑一个。
4. **匹配不到就停。** 如实报“系统内未登记该案”并建议先建案，**不得新建案件**。
5. **不确定就问律师。** 文书类型无法归类、字段该不该填不确定时，问律师，不猜。
6. **如实报告。** 任何一步失败都原样说明错误，给出待填字段清单，不谎称已下载、已上传或已写入。
7. **你能上网。** 用户发来送达链接就是授权你打开并下载文书；不要再说“需要登录、打不开”。下载走下面第 1 步的 OA 工具；查公开网页用 `harness_web_fetch`。

## 第 1 步：下载文书（服务器直接取，存为 OA 附件）

用 `oa_search_tools` 搜“下载法院送达文书”，调用 `POST /documents/court-service/fetch`，`body.link` 填短信里的完整链接。
服务器调法院接口 `getWsListBySdbhNew`（无需登录），逐份下载并保存为附件，返回每份文书的：

- `attachment_id`：后面收文入库时作为 `files.file` 传入；
- `fields`：已识别要素（文书类型、官方案号、主案号解析与检索变体、法院、案由、当事人、开庭、缴费、落款日期、`需人工核对`）；
- `text_excerpt`：正文节选，用来核对识别结果。

同一份文书重复送达时会复用已下载附件（`reused: true`），不会重复保存。接口报“校验失败”多为链接不完整或已过期，请用户重新复制短信链接。
需要只预览、不保存时，可用技能脚本 `scripts/fetch_court_docs.py`（`--list-only`）在沙箱里列清单。

## 第 2 步：核对识别要素

**必提要素**：官方案号、法院、案由、原告/被告、代收律师；缴费类另提金额/期限/账户；传票类另提开庭时间/法庭。
- `需人工核对` 不为空的项必须读 `text_excerpt` 或附件全文复核，仍不确定就问律师。
- 传票与出庭通知书的开庭时间应一致，不一致要报告。
- 扫描件没有正文时如实说明，请律师确认要素，不要按文件名猜。
- 需要单独识别一段文字时，可运行 `scripts/extract_doc_fields.py --name <文书名> --text <正文>`。

## 第 3 步：两级匹配系统案件

**第一级 · 官方案号直配（优先）**：用 `fields.主案号解析.检索变体` 从精确到宽松，作为案件检索的 `keyword` 逐个试（**不能用 `serial_no`**）。
案号字段脏数据约 17%，所以要试多种写法；有多个案号（关联案/一审二审）时必须分别检索确认。
需要单独归一化时运行 `scripts/normalize_case_no.py "<案号>"`。

**第二级 · 当事人 + 受理机关反查（第一级未命中时）**：
`plaintiff`/`defendant` 用去掉“有限公司”等后缀的核心字号 → 收敛到个位数后叠加 `customer` → 仍多再叠加 `court`（存**法院代字**如“皖0402”，不是全称，且可能脏）。

**判定**：1 条 → 继续；2+ 条 → 列候选让用户选；0 条 → 报“系统内未登记该案”并停止。报告须写明匹配级别与依据。
细节见 `references/case-number-formats.md`、`references/oa-system-notes.md`（用 `harness_read_skill_resource` 读取）。

## 第 4 步：官方收文入库

对每份文书调用“上传官方收文”`POST /documents/official/upload`：
- `files.file` = 第 1 步的 `attachment_id`
- `body.case_id` = 第 3 步唯一匹配的案件 ID
- `body.court_case_no` = 文书上的官方案号（归一化后）
- `body.document_date` = 落款日期（没有就用收到日期，并告诉用户）
- `body.remark` = 文书类型

系统自动按“系统案号_法院案号_文书名称”命名，文书进入收文列表并挂到案件；案件尚未登记法院案号时会自动回填。

## 第 5 步：按文书类型回填字段

| 文书类型 | 回填 | 备注 |
|---|---|---|
| 受理通知书 | 法院案号、立案日期 | 第 4 步已回填空缺的法院案号 |
| 传票 / 出庭通知书 | 开庭日期时间、开庭法庭 | 两者交叉核对 |
| 交纳诉讼费用通知书 | 在案件下新建「官方费用」并申请缴纳 | 见下方专项规则 |
| 一审 / 二审判决书 | 一审 / 二审判决日期 | |
| 保全裁定书 | 保全日期 | **必须问律师**是否设保全到期提醒 |
| 撤诉裁定书 / 调解书等 | 相应结案信息 | 不确定归类时问律师 |

案件字段用案件更新接口写入（先用 `oa_search_tools` 确认参数模式）；只补空缺或用户确认要改的字段，案件阶段不手动改。

### 缴纳官方费用专项规则

1. 按审级定费用类型（**不按文书里“案件受理费”等名称猜**）：
   法院案号类型代码优先——`民初/知民初/刑初/行初` → 一审诉讼费（1101010，fee_type_id 19）；`民终/知民终/刑终` → 二审诉讼费（1101020，20）；执行 → 官费（1101090，27）；公证 → 公证费（1101040，22）。案号为空才看案件阶段；都判断不出就问律师。
2. 在案件下新建费用记录并提交缴纳；**最后缴费期限**按文书原文“收到次日起 N 日内”算成具体日期（出具日 2026-10-22、七日内 → 2026-10-29）。
3. **必须询问律师是否设定缴费期限提醒任务**，不得自行决定。
4. 金额与收款账户以文书原文为准；账户要与费用付款类型（`nature=官费`）核对，对不上就问律师。

## 第 6 步：回查确认

写入后回查案件：收文列表里有这份文书、附件大小一致、字段值与文书原文一致、官方费用已进入缴纳流程。有出入立即报告，重复记录不删除，交给用户处理。

## 输出格式

```
【收文处理完成】
来源：{法院}｜案号：{官方案号}
文书：{N} 份（已存为附件 {ID 列表}）
识别要素：案由 {X}｜原告 {X}｜被告 {X}｜开庭 {时间} {法庭}｜缴费 {金额}，{期限}
匹配结果：✅ 唯一匹配（{第一级 官方案号直配 | 第二级 当事人+机关反查}）
  OA案号 {xxx}｜{案件名称}｜阶段 {xxx}｜承办 {xxx}
  匹配依据：{具体维度}
写入：
  1. 官方收文 {文书名}（收文记录 {ID}）
  2. {字段} = {值}（来源：{文书名}）
待律师确认：{问题}
写入状态：✅ 已写入并回查 / ⏳ 部分待写入（原因）
```
